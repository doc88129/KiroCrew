1. 结论与决策

V2 在这批小规模经历检索样本上，能以较少噪声找回大多数相关记忆；向量缺失会明显降低覆盖率，词法准入仍是主要误召回来源。现有证据支持继续受控验证 V2，尚不足以证明整体优于 V1 或启动 V1 迁移。

  • 完整向量：50 个问题中 49 个命中相关记忆（98%），100 个相关片段找回 93 个；候选准入精度 93.94%，上下文 nDCG@8 0.9274。
  • 缺失全部 50 条短片段向量：问题命中仍为 96%，但片段召回从 93% 降至 73%；“还能找到一点”掩盖了内容覆盖的下降。
  • 完全无向量：问题命中降至 74%、片段召回 56%。仍有词法补救能力，不能称为与完整向量等效。
  • 完整向量的 6 条误召回中，5 条仅靠关键词通过准入。优先改进这条路径，并用独立语料复验。

这里的 98% 是记忆主题命中率，不是用户问题的回答准确率；本评测没有生成或评分最终回答。

“缺失短片段向量”不是随机缺失 50% 的模拟。三个模式复用同一批 50 个问题，不是 150 个独立问题，也不是 15,000 个独立问题。所有问题都预设有答案，没有无答案问题集。

主质量集只评测 episodic / 经历检索。事实仅有额外的中日韩结构样例；规则检索、记忆提取/写入正确率、真实长期学习没有对应质量分数。

3. 核心结果与口径

向量状态 候选准入精度（micro） 上下文精度（macro） 片段召回率 问题命中率 上下文 nDCG@8
完整向量 93.94% 93.67% 93% 98%（49/50） 0.9274
缺失全部短片段向量 92.41% 91.00% 73% 96%（48/50） 0.7714
完全无向量 91.80% 71.33% 56% 74%（37/50） 0.5962

指标说明：

  • 候选准入精度：所有问题的 TP ÷ (TP + FP)；这里 admission 是检索候选的相关性准入，不是记忆写入成功率。评测先成功写入全部 100 条经历。
  • 上下文精度：先算每题返回片段中相关片段的比例，再对 50 题平均；空结果按 0 计。它不是固定分母为 8 的 precision@8。
  • 片段召回率：找回的相关片段数 ÷ 100；每题两个正例，使逐题宏平均与该汇总分母一致。
  • 问题命中率：两条等价相关片段中至少找到一条即命中；一次命中不能证明找齐证据、多跳推理成功或回答正确。50 题中一题就是 2 个百分点。
  • nDCG@8：0–1 的排序指标，相关片段排得越靠前越好；不是“百分之多少答对”。

无向量的 91.80% 与 71.33% 并不矛盾：前者只看进入候选的片段；后者对所有问题平均，把空结果也计入。只展示前者会掩盖覆盖率损失。

4. 真正有用的失败分析

4.1 词法补救同时带来噪声

完整向量模式中，99 条通过准入的候选按原因拆分：

准入原因 正确 不相关 观察
语义与关键词同时满足 55 0 本样本中最稳定的一组
仅语义满足 37 1 唯一 FP 的 cosine=0.5724，刚过长片段门槛 0.57
仅关键词满足 1 5 补回 1 条相关片段，同时引入 5 条噪声

仅关键词子集只有 6 条，不能把 1/6 外推为生产精度。但它清楚指出当前样本中的误召回来源：通用词重合不一定代表用户在问同一件事。

9. Schema、按需检索与大规模编辑验证

研究依据与实现选择

LongMemEval 将信息提取、跨会话推理、时间推理、知识更新和拒答分别评测，并研究事实扩展索引与时间过滤。它也指出，把所有经历压成事实会损失上下文。因此本实现保留原始经历，在已有事实旁增加明确身份与有效期。LangChain 的记忆设计文档 说明了集合式记忆与更新协调的取舍；Mem0 的提取与更新分离提供了参考。这里没有引入图数据库或额外服务，也没有把论文中的收益百分比套用到 Kiro Crew。

V1 和 V2 各自在本库中增加 memory_record_meta 与 memory_revisions，保留已有物理表、成员隔离与原始内容。事实身份采用明确的 subject / predicate / scope；类别、来源、观察时间和有效区间帮助区分同一事实的更新与不同实体的相似描述。修订历史保留修改前后内容。

仅在私有 V2 中，自动提取的高 confidence 不能替代用户授权。模糊冲突保留当前事实并记录建议；可验证的用户纠正结合完整的最新用户消息与读取时的 revision，防止过期后台任务覆盖较新的事实。自动更新只接受支持的独立、明确替换语句；不能截掉引用周围的否定、假设、示例或代码来授权。较复杂的表述保留为待审建议。回归样例覆盖有效期、原始证据、虚构纠正、反向替换、否定/假设语句和并发变更；这些是针对性正确性检查，不是新的总体准确率或真实长期对照实验。

以下效果使用真实 SQLite 验证。共享编辑检查覆盖 V1 和 V2，自动提取的冲突与纠正检查仅针对 V2。对应的Schema 回归及编辑与审阅回归验证：

场景 当前结果 能说明什么
稀疏键 user.route_42 只保存地址，查询 Alice billing 未加身份时无匹配；加入 Alice / billing_email 后找回该事实，全程无 Embedding 明确身份能补回该类关键词缺口

V2 的四例更新检查另用旧规则的简化表达式作对照：它在其中三例不符合预期；当前实现四例均符合预期。这是刻意构造的规则对照，不是运行旧版本的 A/B，也不是 75% 准确率提升。 中英文纠正证据还要求消息时间不早于当前事实的更新时间，避免迟到的旧话语覆盖新决定。

V1 的自动合并保留原有语义提示、置信度及来源优先级、置信度 1.0 的来源分类、直接删除旧键、相同值的刷新和用户明确来源的规则写入。共享修订记录与用户编辑不会把这些 V1 策略切换为 V2。V2 自动重新提取已遗忘的同一键时，只保存待审建议，原记录仍不进入召回。

检索与资源变化

V2 消息构建读取核心身份、项目资料和作用域规则；语义及经历片段通过 memory_recall 按需检索。该工具按可信会话选择 Store。V1 首轮保留原有偏好、项目、历史、语义、经历和按查询筛选的规则注入，后续轮次使用原生会话历史。仅 V2 的消息构建检查要求不执行片段召回或查询 Embedding。

同一网关内的内置 Embedding 后端共享一个模型、一个推理工作线程及 128 条缓存；原生推理默认一个计算线程、上限两个。原生等待队列最多八项，保留两个交互位置，每批最多八条，每条输入最多 6,000 字符。它是网关内的资源约束；异步入口按事件循环限流，并非整台机器的全局配额。取消请求也不能立即中断已开始的原生推理，工作位置会保留到推理结束。此处报告的是代码和并发测试验证的资源上限，没有测量不同机器上的真实 CPU/GPU、模型 RSS 或最终响应延迟改善百分比。

Memory MCP 的正文保持 3,000 字符上限，同时对完整记忆结果执行 16 KiB 传输预算。预算计入证据、预览、JSON 多层转义和 TextContent 封装，并为常规 RPC ID／帧头预留 1 KiB；任意超长的调用方 RPC ID 不属于记忆数据预算。结果只携带实际选中的片段、稳定 ID 和精简来源，完整正文仍在管理页。脱敏后再次检查；超限时移除尾部整条结果，并同步更新正文、证据、计数和省略标记。
